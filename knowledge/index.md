## Knowledge layers

- **Mechanics:** what the game rules and systems do.
- **Models:** how mechanics interact economically and operationally.
- **Playbooks:** what to do in a defined situation, with assumptions and decision criteria.

## Trust and lifecycle

Concepts begin as `draft`. A concept should become `stable` only after its important claims have been independently checked and its known limitations are documented. `verified` records actual verification events; it is not a general confidence score.

## Project conventions

- One cohesive concept per Markdown file.
- Use relative Markdown links between concepts.
- Keep volatile market snapshots and personal asset/character data out of static mechanics documents.
- Keep implementation code separate from conceptual explanation.
- Use `log.md` for notable corpus-level changes.
